# 家族共有機能 詳細設計書

## 1. 機能概要
同一世帯（家族）内で、献立、レシピ、在庫、買い物リストをリアルタイムに共有し、複数人で管理する。

## 2. データモデル (schema.md 準拠)
- `households` テーブルでグループを管理。
- `users` テーブルの `household_id` で所属を紐づける。

| カラム名 | 型 | 制約 | 説明 |
| :--- | :--- | :--- | :--- |
| household_id | UUID | NOT NULL | 各データの所有者識別 |

## 3. API設計
- `POST /households`
    - 新しい家族グループを作成（初期ユーザーが管理者）。
- `GET /households/members`
    - 所属している家族メンバー一覧の取得。
- `POST /households/invite`
    - 家族への招待コード（8桁の英数字、有効期限付き）を発行。
- `POST /households/join`
    - 招待コードを入力して家族グループに参加。

## 4. UI/UX設計
- **家族設定画面**:
    - 家族名（例：田中家）の編集。
    - 招待コードの発行と共有ボタン（SNS連携など）。
    - メンバー一覧（アイコンと名前）の表示。
- **データ共有の視覚化**:
    - 買い物リストや在庫の更新が誰によって行われたかを通知。
    - 共通の「買い物リスト」を全員で編集し、一人が購入完了すると全員の画面が更新される。

## 5. ロジック・制約
- **データ分離**: すべてのクエリには `household_id` のフィルタリングを必須とし、他家族のデータへのアクセスを厳格に防止する。
- **共有のタイミング**: フロントエンドでは定期的なポーリング（数分おき）や画面遷移時の最新データ取得を行い、簡便に共有を維持する。
- **権限管理**: 本フェーズでは「全メンバーがフルアクセス可能」というシンプルなルールを採用する。
