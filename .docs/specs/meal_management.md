# 献立管理機能 詳細設計書

## 1. 機能概要
家庭内での1週間の献立を管理するための機能。月曜始まりのカレンダー形式で3食(朝・昼・夕)の献立を設定、レシピの選択、過去の献立のコピー(1ヶ月範囲)を行う。

## 2. データモデル変更 (schema.md)

`meal_plans`テーブルの`meal_type`を`VARCHAR`から`SMALLINT`に変更する。

| カラム名 | 型 | 制約 | 説明 |
| :--- | :--- | :--- | :--- |
| meal_type | SMALLINT | NOT NULL | 0:朝, 1:昼, 2:夕 |

## 3. API設計
- `GET /meal-plans?start_date={YYYY-MM-DD}&end_date={YYYY-MM-DD}`
    - 指定期間の献立情報を取得
- `POST /meal-plans`
    - 特定の日付・食種に対してレシピを割り当て
- `POST /meal-plans/copy`
    - リクエストBody: `{source_start_date, source_end_date, target_start_date}`
    - 指定期間の献立をコピーし、ターゲット期間を上書きする

## 4. UI/UX設計
- **週間ビュー**: 月曜始まりのテーブル。各セルは「日付×食事(朝・昼・夕)」の計21スロット。
- **編集モード**:
    - セルタップでレシピ選択モーダルを表示。
    - レシピ選択モーダルでは「キーワード検索」「過去の献立」「AI提案」「お気に入り」のタブによるフィルタリングを提供。
- **コピー機能**:
    - モーダルまたは専用画面からコピー元期間（過去1ヶ月以内）を選択し、コピーを実行。

## 5. 制約事項
- レシピと献立は独立した概念。
