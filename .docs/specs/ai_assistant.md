# AIアシスタント機能 詳細設計書

## 1. 機能概要
Gemini APIを活用し、ユーザーの要望や冷蔵庫の在庫に基づいた献立の提案、および不足しているレシピの自動生成を行う。

## 2. データモデル (schema.md 連携)
- `recipes` テーブルの `is_ai_generated` フラグを活用。
- 提案された献立は最終的に `meal_plans` テーブルに登録される。

## 3. API設計
- `POST /ai/meal-plan/suggest`
    - リクエスト: `{inventory_ids: [], start_date, end_date, theme: "低糖質"}`
    - レスポンス: 提案された献立リスト（日付、食種、料理名、使用食材）。
- `POST /ai/recipe/generate`
    - リクエスト: `{recipe_title, ingredients: []}`
    - レスポンス: 材料、分量、工程を含むレシピ詳細。

## 4. UI/UX設計
- **提案リクエスト画面**:
    - 「在庫を使い切る」「子供が喜ぶ」「高タンパク」などのテーマをチェックボックスや自由記述で指定。
- **提案プレビュー**:
    - AIが提案した1週間分の献立をカレンダー形式で表示。
    - 個別のメニューを入れ替えたり、特定のレシピを再提案させたりできる。
- **一括登録**:
    - 「この献立を採用」ボタンで、`meal_plans` および（未登録の場合は）`recipes` へ一括保存。

## 5. ロジック・制約
- **プロンプトエンジニアリング**: 
    - ユーザーが保有する在庫情報をコンテキストとして渡し、優先的に消費するよう指示する。
    - 既存のレシピマスタから利用可能な料理を優先的に選択させる。
- **レシピの不整合防止**: AIが生成したレシピは `is_ai_generated=true` として保存し、ユーザーに確認・編集を促す。
